## IMPORTANT

**Do not rebuild the application from scratch.**

# PRIMARY OBJECTIVE

Implement this complete workflow:

```text
Customer sends RFQ email
        ↓
Microsoft 365 / Outlook
        ↓
Email synchronization
        ↓
Email stored in PostgreSQL
        ↓
Attachments downloaded and processed
        ↓
AI analyzes email + attachment text
        ↓
AI extracts RFQ information
        ↓
AI classifies request type
        ↓
Confidence score calculated
        ↓
RFQ created automatically
        ↓
High confidence → Ready for Processing
        ↓
Low confidence → Human Review Queue
```

The system must support development mode with mock email and mock AI data when external credentials are not configured.

```json

  "emailClassification": "RFQ",

    {
      "partNumber": "1234-AB",

      "quantity": 2,
      "condition": "Serviceable",
      "requestedCondition": "Serviceable"
    }
  ],

  "requirements": {
    "certification": [
      "FAA 8130-3"
    ],
    "deliveryRequirement": "ASAP",
    "urgency": "HIGH"
  },

  "summary": "Customer requests quotation for two serviceable hydraulic pumps.",

  "requiresHumanReview": false,

  "reasoningSummary": "Clear RFQ language with identifiable part number and quantity."
}
```

Do not allow malformed AI output to crash the application.

If validation fails, mark the analysis as failed or review-required and preserve the original email.

## Confidence Rules

### High Confidence

```text
>= 0.85
```

Action:

```text
Automatically create RFQ
Status: READY_FOR_PROCESSING
```

### Medium Confidence

```text
0.60 to 0.84
```

Action:

```text
Create RFQ
Send to AI Review Queue
```

### Low Confidence

```text
< 0.60
```

Action:

```text
Create or preserve the analysis
Send to AI Review Queue
Do not automatically finalize the workflow
```
